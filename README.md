# Dev_ancient_naval
Розробка Інді-стратегії відеогри про морський-бій з економікою.

## Прототип 0.00–0.01

Godot **4.7.2 .NET**, C#, .NET SDK 8. Android — первая целевая платформа;
Windows — разработка и проверка. Ориентация горизонтальная.

Реализованы карта 20×20, вода и два фиксированных участка суши, выбор клетки,
подсветка, координаты/тип поверхности, перемещение и масштаб камеры.
Это технический прототип с простыми ромбами, без внешних ассетов.

### Запуск

1. Открыть `project.godot` в **Godot 4.7.2 .NET**.
2. Нажать **Build**, затем **F6** для Main или **F5** для проекта.
   Главная сцена уже назначена: `scenes/Main.tscn`.
3. Нажать на клетку. В левом верхнем углу появятся X, Y и Terrain.

Управление:

| Действие | Windows | Сенсорный экран |
| --- | --- | --- |
| Выбор клетки | Короткий щелчок левой кнопкой | Короткий тап |
| Обзор | Перетаскивание левой кнопкой | Перетаскивание одним пальцем |
| Масштаб | Колесо или кнопки −/+ | Два пальца или кнопки −/+ |
| Возврат к карте целиком | «Вся карта» | «Вся карта» |

Перетаскивание начинается после 12 единиц экранного смещения. Оно не выбирает
клетку при отпускании. После щипка оставшийся палец продолжает обзор.
Потеря фокуса, отменённое касание и изменение размера окна сбрасывают жест.
Масштаб ограничен диапазоном 0.25–2.5. При изменении размеров окна карта
повторно вписывается в экран. Кнопки минимум 64×58 логических единиц.

### Структура и принятые решения

- `src/Core/DevAncientNaval.Core.csproj` — отдельная библиотека .NET без Godot.
  `GridPosition`, `Tile`, `TerrainType`, `GameBoard`: целочисленные координаты,
  поверхность и четыре ортогональных соседа. Коллекция клеток доступна только
  для чтения. Расположение и поверхность клетки задаются при создании карты.
- `src/Presentation/Map/IsometricProjection.cs` — единое место прямой и обратной
  проекции. Целочисленная координата обозначает центр ромба. На общей границе
  выбор детерминирован: клетка с большей соответствующей координатой.
- `BoardView.cs` рисует карту и подсветку. Рисование запускается заново при
  изменении выбора; отдельные узлы или коллайдеры для 400 клеток не создаются.
- `Camera/MapCamera.cs` преобразует координаты через фактическую трансформацию
  камеры. Точка под курсором/серединой жеста сохраняется при изменении масштаба,
  кроме случаев достижения ограничения положения камеры у края карты.
- `Input/MapInput.cs` отделяет жесты от отображения. Начало жеста проходит через
  обработку GUI; активный жест получает отпускание даже над панелью интерфейса.
  Эмуляция мыши от касания оставлена для стандартных кнопок Godot; карта
  игнорирует эмулированные события, чтобы не обрабатывать один тап дважды.
- `UI/DebugHud.cs` — временная панель и кнопки; `Main.cs` связывает компоненты.
- `PrototypeBoard.cs` — фиксированная тестовая карта, не генератор островов.

Будущие корабли, профили действий, обзор, экономика и ИИ будут жить в Core.
Сцена не хранит будущие игровые параметры. Пока эти системы не создавались:
фундамент не навязывает им предположение о единственном источнике дохода или
смешении радара и видимости. Пустые интерфейсы для ещё не реализованных систем
намеренно отсутствуют.

### Проверки

Из корня проекта:

```powershell
dotnet build Dev_ancient_naval.csproj
dotnet run --project tests/CoreChecks/CoreChecks.csproj
& 'PATH/TO/Godot_v4.7.2-stable_mono_win64_console.exe' --headless --path . --quit-after 300 -- --smoke-test
```

Успешный тест Godot обязан напечатать `PASS: 2824 runtime checks`.
`--quit-after` служит ограничителем; само завершение процесса без строки PASS
не подтверждает прохождение тестов. Для визуальной проверки убрать `--headless`.
Необязательный аргумент `--capture=C:/absolute/path/prototype.png` сохраняет
снимок отрисованного кадра и добавляет одну проверку.

Core-проверки работают независимо от Godot и проверяют границы, уникальность
клеток, поверхность, соседей и отсутствие ссылки на движок. Проверки внутри
Godot дополнительно покрывают центры/края ромбов, все клетки после изменения
камеры, клики и касания через viewport, перетаскивание, pinch, отмену касаний,
потерю фокуса, HUD, пределы масштаба и сохранение точки под курсором.
Счётчики включают проверки отдельных клеток, а не тысячи отдельных сценариев.

Пакеты Godot точно зафиксированы на 4.7.2. Обычно они восстанавливаются через
NuGet. В установленной .NET-версии Godot те же пакеты находятся в
`GodotSharp/Tools/nupkgs`; при недоступности NuGet можно указать этот каталог
источником в локальном `NuGet.Config`. Такой файл с путями компьютера исключён
из Git. Кеши, `bin/`, `obj/`, сборки Android и ключи подписи тоже исключены.

### Границы проверки

Проверены сборка C#, импорт ресурсов, выполнение сцены без графики и с
отрисовкой Mobile/D3D12 на Windows. Сенсорные события проверены программно.
Android APK/AAB и физический телефон пока не проверялись; Android SDK/JDK,
экспортные шаблоны и подпись будут отдельным этапом. Ориентация и управление
подготовлены, но это не подтверждение работоспособности Android-экспорта.

Следующий рекомендуемый этап **0.02 — корабль и перемещение**: определение
корабля в Core, размещение на воде, поиск пути по четырём соседям, запас
движения и команда перемещения по тапу. Бой, экономика, туман войны и генерация
секторов остаются отдельными этапами.
